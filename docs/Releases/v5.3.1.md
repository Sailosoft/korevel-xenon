# Version 5.3.1 — Specs Patch Engine, Enhance Mode, Diagram PNG Export & Mobile Speech

- **Version:** v5.3.1
- **Release dates:** 2026-10-27, 2026-10-30, 2026-11-12
- **Commits:** `82e5e72` → `8f0e5cc` (base `7a0a619`, v5.3.0)
- **Apps:** Bunny Developer, Bunny Book, Bunny(1st): Book Builder, Catalog, Helix, System
- **Stats:** 40 files changed, 4,217 insertions(+), 1,448 deletions(-)

## Summary

Version 5.3.1 hardens the **Specs** AI workflow. Document generation and the AI
Document Assist wizard no longer rewrite whole documents; they return **patch
operations** that are applied only to the regions they target, reviewed in a
unified before/after diff, and staged in the document until the user saves or
discards them. The wizard also gains an **Enhance** mode that asks the AI to
find the biggest gaps first. Elsewhere, the Schema Builder gains drag-and-drop
column ordering, the Diagram Builder and Schema ERD gain PNG export, Bunny Book
gets mobile-safe text-to-speech in both the reader and the HTML export, and
Helix adds a configurable local Ollama endpoint with a refreshed cloud model
catalog.

No Dexie migration is required for this patch release.

## Highlights

### Bunny Developer — Specs AI Patch Engine

- AI generation with `append`, `update` and `replace` modes now calls the new
  **`bdPatchSpec`** server action instead of regenerating a full document.
  `create` keeps using `bdGenerateSpec`.
- New client-safe module **`BDSpec.Patch.ts`** defines the patch DSL:
  - `setMeta` — name, summary, status and type.
  - `updateSection` — update an existing section by id, anchor or exact title.
  - `insertSection` — insert a section after a target or append it.
  - `deleteSection` — remove a section by id, anchor or title.
  - `replaceSections` — replace the ordered section set.
  - `replaceContent` — replace an anchored content region in single-document
    mode using start/end patterns.
- `applySpecPatches` applies operations in order and preserves the identity of
  everything it does not touch (section ids, anchors and positions). Failures
  throw `BDSpecPatchError` with the failing operation index and name.
- Patch prompts are budgeted to **60,000 characters** using compact JSON
  (`serializeSpecTarget`). Append/update requests use a 16,000-token budget;
  replace may use 32,000 for a complete section set.
- Single-document specs use anchored content patches; sectioned specs use section
  operations. The server prompt explicitly forbids returning the whole document
  for append/update.
- New shared **`BDTextPatch`** engine — an inclusive start/end anchored region
  replacement applied sequentially with whitespace-tolerant matching, a 30-word
  pattern cap and a typed `BDTextPatchError`. File-management AI patches
  (`BDFile.Patch`) were refactored onto it, removing ~190 lines of duplication.
- New **`BDSpecChangesView`** review surface: lists every operation with
  add/update/delete icons and renders a unified line diff of the rendered
  document before and after.

### Bunny Developer — Specs Review, Staging & Save

- AI generation and refine results are now **staged**, not written immediately:
  - Applying generated patches from the spec group page stores them in
    `sessionStorage` (15-minute handoff) and routes to the document.
  - The document detail page consumes the handoff only when there is no local
    draft, so in-progress edits are never clobbered.
  - A blue **AI changes staged** banner shows the operation count with
    **Review changes** and **Discard** actions. Saving persists the staged
    document; discarding restores the pre-AI baseline.
- The AI refine wizard now accumulates patch operations across turns and stages
  them for the final Save instead of applying a partial `BDSpecRecord` update.
- The document action **AI Refine** is renamed **AI Assist**.
- `BDGenerationPanel` gained `getAppliedToast` and `getReviewDescription` props,
  and Specs uses them to explain that generated changes are staged for review
  rather than saved on apply.

### Bunny Developer — Specs Enhance Mode

- AI Document Assist now offers two modes:
  - **Refine** — the user picks a refinement type and depth, then answers
    targeted questions.
  - **Enhance** — the AI analyzes the document first, returns a summary and a
    list of improvement areas with recommended flags, and the user selects the
    areas to focus on before answering questions.
- New `bdAnalyzeSpecEnhancement` server action and analysis phase, with
  **Retry analysis** and **Ask questions** actions.
- New optional instruction field (2,000-character limit) that applies to both
  modes and is carried into every question and revision call.
- Recommended areas are preselected; Enhance defaults to the `high` depth.

### Bunny Developer — Schema Builder

- Model columns can now be **reordered by drag and drop**. Each row gains a grip
  handle, and a blue before/after insertion line shows where the column will
  land. Reordering edits the draft only; Save persists the new order.
- Schema ERD PNG export now reuses the shared diagram rasterizer instead of its
  own duplicate implementation.

### Bunny Developer — Diagram Builder & ERD Export

- Diagram Builder gains **`.png` export** next to `.mmd`, `.md` and `.svg`, from
  both the inline preview and the full-screen preview modal.
- New `svgToPngBlob` in `BDDiagramExport.ts`:
  - 2× raster scale by default.
  - White background so diagrams read on dark UIs.
  - Longest-side cap of 8,192 px, with the scale reduced automatically.
  - Size resolved from the SVG width/height, then `viewBox`, then the canvas
    natural size, so Mermaid's `width="100%"` cannot collapse the image.
- The Schema ERD export now uses the same rasterizer.

### Bunny Book — Mobile-Safe Text-to-Speech

- New `bui.book-chapter.speech.ts` helper that mirrors the proven Bunny Studio
  voice approach:
  - Strips Markdown and formatting before speaking.
  - Splits long chapters into sentence-sized chunks (180 characters) so mobile
    engines do not truncate them.
  - Prefers an installed local English voice and falls back to any English
    voice, warming the voice list on mount.
  - Unlocks the engine from a user gesture and avoids cancelling a freshly
    loaded engine immediately before `speak()`.
  - Resumes Android Chrome queues with a 10-second watchdog.
  - Reports a start timeout after 1.5 seconds instead of silently doing nothing.
- The chapter reader now shows `starting`, `speaking` and `error` states, a
  spinner, chunk progress (`3/12`) and actionable hints for silent mode, volume
  or missing voices. Unmount and repeated taps cancel the active session.
- The **GitHub HTML export template** now ships the same chunking, voice
  selection, resume watchdog and failure hints inside the exported document.

### Bunny(1st): Book Builder

- “Automatically generate all chapters” now defaults to **on** for new books,
  after a bulk generation completes and when the book form is reset.

### Helix & Docker

- The local Ollama OpenAI-compatible endpoint is now configurable with the new
  **`OLLAMA_LOCAL_BASE_URL`** environment variable (default
  `http://localhost:11434/v1`). It is read once at module load and drives both
  the chat and transcription endpoints.
- `docker-compose.yml` passes `OLLAMA_LOCAL_BASE_URL` to both the production and
  development services, defaulting to `http://host.docker.internal:11434/v1`.
- `.env.example` documents the variable, including the requirement that Ollama
  listen on `0.0.0.0` for container access.
- The Ollama Cloud model catalog was refreshed to 22 models, including DeepSeek
  V4 Pro / V4.1 Flash, GLM 5.2 / 5.3 / 5.3 Flash, Kimi K2.6 / K2.7 Code / K3 /
  K3.1 Pro, MiniMax M3 / M3.1 Flash, Mimo V2.6 Flash / Pro, Mistral Large 4,
  Beam, Clef, Muse Spark Open, Gemma 4, GPT-OSS and Nemotron 3.
- Local Ollama gains `gemma3:4b`; the Ollama Cloud catalog is shared with the
  local provider as before.

### Catalog

- The Releases page collapse animation now uses CSS grid rows instead of a fixed
  max-height, so long entries no longer clip while expanding.
- Collapsible sections expose `aria-expanded` and set `inert` while collapsed.

### Editor, Docs & System

- Upgraded **`@mdxeditor/editor` from 3.55 to 4.3.4** and added
  `@tailwindcss/typography` with `@plugin "@tailwindcss/typography"` in
  `globals.css`.
- New lazily loaded **`BunnyMarkdownSurface`** (`ssr: false`) replaces the
  duplicated inline MDXEditor setup in `BunnyMDXEditor` and
  `BunnyDialogFieldBuilder`. The wrapper owns sync guards so external value
  changes do not echo back as edits.
- **`BLEditor`** was rewritten on the client-only surface with a toolbar:
  undo/redo, bold/italic/underline, lists, links, tables and code blocks
  (JavaScript, TypeScript, CSS and HTML via CodeMirror).
- `BDWysiwygEditor` now uses the same last-emitted/last-prop guard and prose
  typography classes, removing redundant `setMarkdown` calls.
- The Outline module README was expanded with the generation modes, item
  pipeline and review flow, and the Mermaid reference diagram was refreshed.

### Upgrade Notes

- Set `OLLAMA_LOCAL_BASE_URL` **with the `/v1` suffix** and restart the server
  after editing `.env`; the value is read at module load.
- In Docker, use `http://host.docker.internal:11434/v1` and ensure Ollama is
  reachable from the container.
- The MDXEditor upgrade is a major version change; verify custom editor styling
  in any module not covered by the shared surface.
- No Dexie schema version bump or data migration is included in this release.
